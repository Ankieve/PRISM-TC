What this pipeline does not do yet
  • No storm identification - the model only classifies an image someone has already cropped to a storm; it cannot find or detect a cyclone inside a wider satellite frame.
  • No multi-source fusion - TCIR feeds the AI classifier, IBTrACS feeds the separate analog track/backtest logic, and ERA5 feeds a separate rule-based environment check. Nothing is combined into one model.
  • Prediction is not AI - the 24h track/intensity outlook copies the closest historical storm (analog method), not a learned forecast.
  • Confidence is a derived estimate, not a measured probability - it comes from the wind estimate and the model's own measured test MAE (10.2 kt) via a Normal-distribution assumption, not a calibrated softmax. No Expected Calibration Error has been computed for it (the old v2 model's ~27% ECE does not carry over). The rarest storm classes still have as few as 26-30 test images, so treat rare-class accuracy with caution.

      References & Glossary

      The published methods and datasets this prototype actually builds on

      References
      • TCIR dataset (Chen et al., 2018, "Rotation-blended CNNs for tropical cyclone intensity estimation from multi-source data") - source of the infrared chips the classifier is trained and tested on.
      • IBTrACS (Knapp et al., 2010, "The International Best Track Archive for Climate Stewardship") - historical positions/winds behind track_data.csv and the analog track/backtest methods.
      • EfficientNet (Tan & Le, 2019, "EfficientNet: Rethinking Model Scaling for Convolutional Neural Networks") - the classifier's architecture (EfficientNet-B0, via timm).
      • Atkinson-Holliday pressure-wind relationship (1977) - the rule used to estimate central pressure from wind speed.
      • IMD cyclone intensity classes and wind bands - the 5-class scheme (Depression through Extremely Severe/Super Cyclone) used throughout.
      • Temperature scaling (Guo et al., 2017, "On Calibration of Modern Neural Networks") - the confidence-calibration method in backend/calibration.py.
      • Grad-CAM (Selvaraju et al., 2017, "Grad-CAM: Visual Explanations from Deep Networks via Gradient-based Localization") - the saliency-overlay method in backend/gradcam.py.
      • INSAT-3D/3DS (India Meteorological Department) - source of the near-real-time satellite imagery on this dashboard.
      Glossary
      • ECE (Expected Calibration Error) - how far a model's stated confidence is from its actual accuracy; 0% is perfectly calibrated.
      • Macro-F1 - the F1 score averaged equally across all 5 classes, so rare classes count as much as common ones (unlike plain accuracy).
      • Analog method - a rule-based technique that copies the future behavior of the closest-matching historical storm; not machine learning.
      • Grad-CAM - a heatmap showing which pixels most influenced a classifier's decision; a debugging aid, not proof of correct reasoning.
      • OOD (out-of-distribution) - an input that looks unlike anything the model was trained on, so its output can't be trusted normally.
      • Temperature scaling - dividing a model's raw scores by a learned constant before the final probability step, to make its confidence less overconfident without changing its predictions.
      • Rule-based vs. ML - "rule-based" means a fixed formula a person wrote (e.g. the SST/wind-shear check); "ML" means a pattern learned from training data (only the image classifier here is ML).

      API Reference

      Every HTTP endpoint this server exposes - for reproducing a result, scripting against it, or reusing the backend in your own research

      This is a stdlib Python HTTP server (no framework) - every route below is implemented in backend/server.py. Field-by-field request/response shapes are documented in the repository's CLAUDE.md ("API contract" section) for anyone cloning the code. All responses are JSON; errors are {"error": "message"} with a non-2xx status code.

      Prediction

      GET /api/health

      Server + model status: whether the real model.pth is loaded, and which optional features (Grad-CAM, ERA5) are available on this server.

      GET /api/samples

      The 10 built-in TCIR test images with their true class, storm id and position.

      GET /api/demo?i=N

      Runs a prediction on the next (or the i-th) built-in sample image - same response shape as /api/predict, plus the true label.

      POST /api/predict

      The core endpoint. Body: latitude, longitude, wind, pressure, an optional sample filename or base64 image, and optional sst, wind_shear, humidity, vorticity, environment_source for the rule-based environment check. Returns the intensity class + confidence (REAL, AI model) plus a simulated track/wind/risk outlook - see the tags in the response's sources field for exactly which is which.

      Model evaluation & transparency

      GET /api/model/transparency

      Structured JSON version of the Model Transparency panel: accuracy, macro-F1, ECE, calibration status and known failure modes.

      GET /api/backtest/storms

      Which real historical storms in track_data.csv have enough following positions to be backtested.

      POST /api/backtest/run

      Body: {"storm_id": "..."}. Tests the analog track method (not the AI classifier) against that storm's real recorded track, always excluding the storm from its own candidate pool. Returns track error (km) and wind error (kt) per 3-hour step - a fully reproducible accuracy number for the simulated outlook.

      Near-real-time satellite

      GET /api/satellite/status

      Current LIVE / STALE / UPDATING / ERROR / NO_DATA status plus source metadata (also at /api/satellite/latest).

      GET /api/satellite/metadata

      Just the source/product/timestamps, no status logic.

      GET /api/satellite/image

      The latest cropped North Indian Ocean PNG.

      GET /api/satellite/history

      Recent update history (source, timestamp, status per check).

      POST /api/satellite/update

      Triggers one manual check-and-update cycle immediately, instead of waiting for the background poller.

      ERA5 reanalysis OPTIONAL

      GET /api/era5/status

      Whether cdsapi/xarray are installed and a Copernicus CDS API key was found on this server - never makes a network call, safe to poll.

      GET /api/era5/fetch?lat=&lon=

      Real SST / wind-shear / humidity / vorticity for one point from ERA5 (Copernicus Climate Data Store). Needs the operator's own free CDS account - see backend/era5.py for setup and important honesty notes about reanalysis lag (it is real data, but never real-time).
